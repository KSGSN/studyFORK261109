# 스터디 설명 편집 도구

## 서버·로그인 없이 사용

현재 설명 편집은 별도 저장 서버에 접속하지 않습니다. 사이트가 열리면 각 프로젝트 폴더의 `descriptions.json`을 자동으로 읽습니다. 설명·화면 개요·알럿/컨펌·핀 위치는 현재 브라우저의 localStorage에 프로젝트별로 보관됩니다. 브라우저 임시 편집본이 있으면 작업 보호를 위해 저장소 파일보다 우선합니다. 저장소 최신 설명을 보려면 백업 후 **저장소 JSON 적용** 버튼으로 임시 편집본을 버리세요. 임시 편집본이 없는 방문자는 새로고침할 때 최신 저장소 JSON을 읽습니다.

상단 도구에서 설명을 열고 **영역에 설명 추가**로 작성하세요. 기존 소스에 들어 있는 기준 명세는 그대로 유지하며, JSON에는 편집 도구로 저장한 데이터만 담깁니다.

- **JSON 내보내기**: 현재 프로젝트의 모든 화면 설명과 핀 위치를 JSON 파일로 다운로드합니다. 편집 후 반드시 파일을 보관하세요.
- **JSON 불러오기**: 같은 프로젝트에서 내보낸 파일을 선택합니다. 확인 후 현재 프로젝트 전체 설명을 교체합니다. 다른 프로젝트나 잘못된 파일은 거절하며 기존 데이터는 유지합니다. 합치기 기능은 아닙니다.
- 다른 PC·브라우저에서는 Git에 올린 `descriptions.json`이 자동으로 적용됩니다. 아직 Git에 올리지 않은 임시 편집본을 옮길 때는 JSON을 직접 불러오세요. 브라우저 데이터를 삭제하면 임시 보관 내용도 사라집니다.
- 편집하거나 JSON을 내려받아도 HTML·JS 소스와 GitHub 파일은 자동으로 변경되지 않습니다. JSON 파일을 폴더나 GitHub에 직접 보관할 수 있습니다. 내보낸 파일을 해당 프로젝트 폴더의 `descriptions.json`으로 교체하고 Git에 올리면, 배포 후 다른 방문자는 자동으로 읽습니다.
- 기존 서버에 저장했던 데이터는 자동 이전되지 않습니다. 이 JSON 형식으로 내보낸 데이터만 가져올 수 있습니다.

## 로컬 실행

저장소 루트에서 다음 명령을 실행하고 브라우저에서 로컬 서버의 프로젝트 페이지를 여세요.

```sh
python3 -m http.server 8000
```

HTML을 더블클릭한 `file://` 방식에서는 JSON 자동 읽기가 차단될 수 있으므로 위 정적 서버 방식으로 실행하세요. 이 서버는 파일 제공만 하며 별도 로그인·저장 서버는 필요 없습니다.

## 검증

Playwright와 Chromium이 있는 환경에서 정적 서버를 실행한 뒤:

```sh
STUDY_TEST_URL=http://127.0.0.1:8000 CHROMIUM_PATH=/usr/bin/chromium node common/tests/local-descriptions.cjs
```

## 팀원 추가
자신의 폴더를 만들고 루트 `index.html`에 링크를 추가합니다.
`body data-project`를 고유 ID로 지정하고 화면에는 고유 ID를 등록합니다.
`mjha/index.html`과 `mjha/include/app.js`의 빈 구조를 참고하세요.
공통 도구는 `../common/`에서 불러오며 자기 폴더에 복제하지 않습니다.

## Git으로 설명 배포하기

1. 브라우저에서 설명을 편집합니다.
2. **JSON 내보내기**로 `descriptions.json`을 받습니다.
3. 해당 프로젝트 폴더(예: `yjgeum/descriptions.json`)의 파일을 교체합니다. 다른 프로젝트 폴더에 넣으면 프로젝트 검증에서 거절됩니다.
4. Git에 커밋·푸시하고 Pages 배포 완료 후 새로고침합니다.
5. 편집하던 브라우저에서는 **저장소 JSON 적용**으로 임시 편집본을 정리하면 이후 저장소 변경을 자동으로 봅니다.

현재 남아 있는 yjgeum 프로젝트에 빈 설명 JSON을 추가했습니다. 기존 소스 기준 명세는 유지됩니다. JSON에는 편집 도구로 작성한 내용만 포함됩니다. 저장소 JSON 오류는 화면에 표시하며 브라우저 편집본을 자동 삭제하지 않습니다.
