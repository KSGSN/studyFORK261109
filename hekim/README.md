# YEOJEONG 웹 기획안

여행 추천·일정 관리 서비스의 UI 및 기능 검토용 정적 프로토타입입니다. HTML5 / CSS3 / Vanilla JavaScript를 사용하며 빌드, 서비스 백엔드, DB가 필요하지 않습니다.

## 확인 방법

- GitHub Pages: `https://with-demo.github.io/study/hekim/index.html#HOME-01`
- 저장소 루트에서 `python -m http.server 8000` 실행 후 `http://localhost:8000/hekim/index.html`에 접속합니다.
- `hekim/index.html`을 직접 열 수도 있습니다. 브라우저/조직 정책이 파일 URL이나 브라우저 저장소를 차단하면 정적 서버 방식을 사용하세요.
- 화면은 검정 공통 도구의 화면 선택 / 화면검색으로 이동합니다. 별도 프로젝트명 줄과 좌측 사이트맵은 제거된 상태입니다.
- **디스크립션 열기**: 우측 기준 명세와 빨간 번호를 표시합니다. 번호와 설명 카드의 숫자를 누르면 서로 연결된 위치를 확인합니다. 최초 방문 시 닫힘이 기본이며 현재 탭의 선택을 유지합니다. 1100px 이하에서는 설명이 아래로 배치됩니다.

## 구현 범위

엑셀의 20개 화면 전체를 구현했습니다. Lv1~Lv3와 원본 행 매핑은 `docs/sitemap.md`에 있습니다. 최신 첨부 엑셀은 기존 원본과 SHA-256이 동일함을 확인했습니다. 화면 ID는 기존 북마크를 유지합니다.

| 기능 | 동작 |
|---|---|
| 메인 | 검색 진입, 국내·해외 인기 카드, 일정 만들기 |
| 계정 | 약관동의, 데모 가입, 모의 로그인·유지, 아이디 찾기, 모의 이메일 인증/재설정 |
| 여행지 | 지역·테마·키워드 검색, 정렬, 상세·가이드, 추천 일정 목록·상세 |
| 나의 여행 | 등록·조회·수정·삭제, 추천 일정 복사, 날짜별 장소 추가·수정·삭제·순서 변경, 날짜 메모 저장 |
| 마이페이지 | 예시 프로필 수정, 비밀번호 변경 절차, 로그아웃, 탈퇴, 초기화, 찜 목록·해제 |
| 고객지원 | 공지 검색·상세·예시 첨부 다운로드, FAQ 필터·펼침, 문의 등록·수정·삭제 및 파일 저장·다운로드 |
| 기획 명세 | 각 화면의 개요와 요소별 항목·유형·기본값·필수여부·기능·검증·정책·예외·연결 화면 |

## 데모 계정과 저장

- 입력 없이 **데모 계정으로 시작** 버튼을 사용할 수 있습니다.
- 최초 아이디는 `demo`입니다. 로그인 폼은 **임의의 8자 이상 비밀번호**를 입력하면 진행합니다. 실제 인증을 하지 않으며 비밀번호는 저장하거나 외부로 전송하지 않습니다.
- 아이디 찾기 예시: 이름 `여행자`, 이메일 `traveler@example.com`. 모의 재설정 인증번호는 화면에 표시되는 `123456`입니다. 이메일은 발송되지 않습니다.
- 데모 가입 후에는 입력한 아이디를 사용합니다. 브라우저당 하나의 프로필만 다루며 가입 확인 시 이전 실습 데이터가 초기화됩니다. 실제 개인정보나 사용하는 비밀번호는 입력하지 마세요.
- 여행·프로필·찜·문의·첨부파일은 `yeojeong.prototype.v2` 키의 localStorage에 저장합니다. 로그인 유지 미선택 시 sessionStorage, 선택 시 localStorage에 모의 상태만 저장합니다. 다른 기기와 공유되지 않습니다.
- 일정 편집은 초안을 만들며 **일정 저장**으로 전체 날짜를 반영합니다. 같은 탭 내 화면 이동 시 초안을 유지합니다. 새로고침·종료 시 미저장 경고를 제공합니다. 취소는 확인 후 초안을 버립니다.
- 여행은 1~30일, 하루 최대 20개 장소를 지원합니다. 기간 축소는 확인 후 뒤 날짜를 제거하며 날짜 변경 시 DAY 순서대로 일정을 유지합니다.
- 문의 파일은 PNG / JPG / PDF / TXT 1개, 최대 2MB입니다. 브라우저 전체 저장 용량이 부족하면 오류를 표시하고 원본은 유지합니다. 신규 문의는 답변 대기이며 실제 관리자에게 전달되지 않습니다. 최초 예시 1건에만 샘플 답변을 제공합니다.
- 마이페이지의 **실습 데이터 초기화**로 최초 상태를 복원할 수 있습니다. 탈퇴는 저장 데이터를 비우고 로그아웃합니다.

## 수정 위치

| 파일 | 역할 |
|---|---|
| `index.html` | 공통 도구 및 스크립트 연결 |
| `style.css` | 서비스 UI, 반응형, 우측 명세·번호 핀 스타일 |
| `data/screens.js` | 화면 ID, 메뉴 계층, 엑셀 원본 개요 |
| `data/demo.js` | 여행지·명소·공지·FAQ 예시 데이터 |
| `data/descriptions.js` | 화면별 기준 명세. `key`로 화면의 `data-description-key`와 연결 |
| `include/store.js` | 실습 데이터 초기값, 브라우저 저장, 모의 로그인 |
| `include/core.js` | 링크·폼·모달·일정·오류 안내 공통 함수 |
| `include/views.js` | 20개 화면 렌더링 |
| `include/app.js` | 라우팅·검색·저장·삭제·폼 검증 등 이벤트 처리 |
| `include/description-viewer.js` | 기존 공통 패널에 기준 명세와 번호 핀 연결 |
| `assets/*.svg` | 로컬 풍경 일러스트, 외부 이미지 요청 없음 |
| `docs/descriptions.md` | 20개 화면 · 75개 요소별 기준 명세 검토 문서 |
| `tests/prototype.cjs` | 브라우저 회귀 검증 |

기준 명세는 로그인 없이 표시하는 소스 관리 데이터이며 서버에 자동 업로드하지 않습니다. 기존 `../common/` 도구는 상대경로로 참조합니다. 공동 GitHub 로그인·설명 편집·서버 저장과 서비스 데모 로그인·브라우저 실습 저장은 서로 독립적입니다. 공동 편집 서버의 권한이나 저장 성공을 이 프로토타입의 모의 로그인으로 대신하지 않습니다.

추가 팝업은 부모 화면 ID의 `-p01`(확인), `-p02`(입력) ID를 사용하고 닫기 버튼에 접근성 이름을 제공합니다. 팝업은 원래 화면에서 열며 해당 동작의 기준 명세에 연결 ID와 정책을 기록합니다.

## 브라우저 검증

Playwright가 설치된 개발 환경에서 정적 서버를 실행한 후:

```sh
YEOJEONG_TEST_URL=http://127.0.0.1:8000/hekim/index.html node hekim/tests/prototype.cjs
```

별도 Chromium 사용 시 `CHROMIUM_PATH=/usr/bin/chromium`을 설정합니다. Playwright는 개발 검증용이며 서비스 실행에는 필요하지 않습니다. 테스트는 기존 공동 편집 서버 응답을 격리해 정적 서비스만 검증합니다.

Chromium에서 20개 화면·기준 명세·번호 핀, 여행지 검색·찜 유지, 추천 일정 복사, 여행 CRUD, 장소 편집·정렬·메모 저장, 문의 CRUD·파일 다운로드, 공지·FAQ, 모의 계정 흐름, 390px 모바일 넘침, 뒤로/앞으로가기 및 JavaScript 오류·로컬 리소스 누락을 검증했습니다. 저장 차단 시 원본 유지, 첨부 확장자·용량 제한, 삭제 취소 및 미저장 초안 취소도 확인했습니다. 실제 이메일 발송·회원 인증·공동 서버 쓰기·관리자 상담 처리는 제공하거나 검증하지 않습니다.
