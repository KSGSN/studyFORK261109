# YEOJEONG 웹 기획안 · 1차

HTML5 / CSS3 / Vanilla JavaScript. 빌드·백엔드·DB 없이 동작합니다.

## 실행

- `hekim/index.html`을 브라우저에서 엽니다. 일반 script 및 상대경로를 사용하므로 화면 데이터 로딩에 서버가 필요하지 않습니다.
- 브라우저/조직 정책이 파일 열기를 제한하면 저장소 루트에서 `python -m http.server 8000`을 실행하고 `http://localhost:8000/hekim/index.html`에 접속합니다.
- GitHub Pages가 저장소 루트를 게시하도록 설정되면 `/study/hekim/index.html#HOME-01` 경로로 접근합니다. GitHub Pages 설정은 저장소 Settings → Pages에서 확인할 수 있습니다.

## 파일 및 수정 위치

| 파일 | 역할 |
|---|---|
| `index.html` | 기획안 레이아웃, 기존 공통 도구 로딩 |
| `style.css` | 뷰어 및 서비스 공통 디자인, 반응형 스타일 |
| `data/screens.js` | 20개 화면 ID, Lv1~Lv3 계층, 기능 설명, 구현 상태, 원본 행 |
| `include/app.js` | 해시 라우팅, 메뉴, 메인 렌더링, 필터 및 검색 진입 |
| `assets/*.svg` | 자체 제작 풍경 일러스트, 외부 요청 없음 |
| `docs/sitemap.md` | 원본 메뉴와 화면 ID 대응표 |
| `여정 사이트맵 및 기능정리.xlsx` | 채팅 첨부 원본, 내용 변경 없음 |

새 화면은 `data/screens.js`의 정의를 유지하고 `include/app.js`의 렌더링 분기에 추가합니다. 해당 화면 구현이 끝나면 `implemented` 값을 변경합니다. URL ID는 북마크 호환을 위해 유지합니다. 기능 정의는 `description`에서 수정하면 하단 설명 및 공통 도구 개요에 반영됩니다.

## 원본 분석 및 범위

작업 시작 시 로컬 `hekim` 폴더에 원본 엑셀이 없어 동일 이름의 채팅 첨부를 사용했습니다. sheet1의 4~23행을 20개 화면으로 매핑했습니다. 빈 상위 메뉴는 직전 Lv1·Lv2를 상속합니다. ID는 원본에 없어 신규 정의했습니다. 세부 매핑은 `docs/sitemap.md`를 참고하세요.

참고 URL은 프록시 403으로 접근하지 못하여 그 페이지의 세부 구성을 추정하지 않았습니다. 사용자 요구사항 및 저장소의 기존 `../common/` 도구를 사용했습니다. 공동 Description 편집기는 기존 연결을 유지하며, 하단의 원본 기능 정의는 로그인 없이 항상 확인할 수 있습니다. 공동 설명 저장/인증의 성공 여부는 이번 작업의 검증 범위가 아닙니다.

메인에서 서비스 메뉴, 여행지 카드, 일정 시작 버튼은 해당 제작 예정 화면으로 이동합니다. 국내/해외 필터는 즉시 동작합니다. 검색은 공백 입력을 검증하고 여행지 목록의 제작 예정 화면으로 이동합니다. 실제 검색 결과, 인증, 등록·수정·삭제·찜과 localStorage 저장 기능은 후속 작업입니다. 현재 사용자 계정이나 비밀번호는 수집하지 않습니다.

## 검증

Chromium 1440px / 모바일 390px에서 공통 도구의 20개 화면 선택, 모든 제작 예정 화면, 해시 이동, 뒤로/앞으로가기, 국내/해외 필터, 공백 검색 오류, 미등록 ID 안내, 모바일 가로 넘침 및 JS 오류를 확인합니다. 파일 직접 열기는 실행 환경 Chromium의 조직 정책으로 차단되어 정적 HTTP 서버로 검증합니다.

## 레이아웃 변경

별도의 프로젝트명 표시 줄과 좌측 사이트맵은 제거했습니다. 화면 전환은 기존 공통 상단 도구의 화면 선택 및 화면검색으로 제공합니다.
